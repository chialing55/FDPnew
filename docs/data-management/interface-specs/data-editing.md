# 資料輸入與修改介面規範

> 分類：資料管理系統／介面規範
> 參考現行介面：GEO-TREES、死亡率調查、福山小苗、種子雨、小苗實驗

本文件規範「建立調查、輸入、續傳、修改、特殊修改與完成調查」的頁面結構及操作行為。Handsontable 本身的欄寬、列高、編輯器、驗證顯示及捲動方式另見 [Handsontable 資料輸入介面規範](handsontable.md)。研究專屬欄位、代碼、狀態轉換、特殊值與完成條件，寫在各研究的資料輸入文件及頁面注意事項。

## 一、規範層級

新增或重整介面時依下列順序判斷：

1. 本文件：頁面骨架、操作狀態、儲存與修改行為。
2. Handsontable 規範：表格呈現與前端互動。
3. 研究文件：欄位、合法值、資料關聯、完成條件與例外。

現有舊頁面可以繼續使用；修改舊頁面或建立新頁面時逐步套用本規範，不得為了外觀統一而改變研究資料邏輯。

### 文件責任邊界

| 項目 | 本文件 | Handsontable 文件 |
| --- | --- | --- |
| 頁面標題、卡片、note、按鈕 | 定義 | 不定義 |
| 建立、續傳、修改、刪除、完成流程 | 定義 | 不定義 |
| 權限、transaction、稽核與完成條件 | 定義 | 不定義 |
| 表格欄寬、列高、捲動與編輯器 | 僅引用 | 定義 |
| instance、draft、dirty、Livewire 重繪 | 僅提出流程要求 | 定義實作 |
| 錯誤訊息內容與儲存結果 | 定義流程要求 | 定義儲存格定位及回傳格式 |
| 研究欄位與狀態規則 | 由研究文件定義 | 由研究設定提供 |

## 二、標準工作模式

### 2.1 建立調查批次

- 適用於需要先建立日期、月份、人員或固定名單的工作。
- 批次資料與逐筆紀錄分開保存。
- 建立前顯示必要欄位及最近批次，避免重複。
- 尚有未完成批次時優先顯示「繼續輸入」，不得無提示建立下一批。
- 允許略過調查時，必須限權限、二次確認並保存略過狀態。
- 建立、開始輸入、完成輸入是不同狀態，不只靠畫面文字推測。

### 2.2 新資料輸入

- 用於新調查批次或尚未建立的正式紀錄。
- 可依樣站、樣區、map、Plot、頁次或調查順序分組。
- 每個工作單位可分次儲存；成功只代表該次送出已寫入，不等於整批完成。
- 固定名單型由後端提供識別欄與順序；空白表型才允許新增列。
- 若分暫存表與正式表，頁面須說明一般儲存寫入哪一層，以及完成後的檢查或匯入。

### 2.3 繼續未完成輸入

- 重返頁面時載入未完成批次與已儲存內容。
- 顯示批次、日期、狀態及「繼續輸入」。
- 已儲存資料與瀏覽器未儲存草稿不可混為一談。
- 切換工作單位或離頁仍有未儲存變更時必須提示。

### 2.4 修改既有資料

- 先搜尋或選擇修改範圍，再載入目前值。
- 頁面及卡片標題明確標示「資料修改」。
- 清楚區分唯讀識別欄與可修改調查欄。
- 只更新允許修改且實際變更的欄位。
- 沒有變更時不送出無意義更新，提示「沒有需要儲存的修改」。
- 成功後回報筆數；需要時保存修改者、時間、原因與前後值。

### 2.5 特殊修改

用於樣區、編號、物種、原量測值等背景或識別資料修正；不是每個研究都必須提供。

- 與一般量測分開，主表不可直接改動識別關聯。
- 由資料列上的明確圖示或按鈕開啟並顯示操作對象。
- 只填需修改欄位；空白代表不修改。需要清除值時另設明確操作。
- 主表有未儲存內容時先儲存；主表驗證失敗便不開啟特殊修改。
- 有獨立驗證與儲存按鈕，成功後同步更新畫面。
- 唯一鍵、外鍵或跨期資料由後端檢查衝突。

### 2.6 新增個體或新增列

- 固定名單外的新個體使用獨立「新增」區塊，不直接插入既有固定列。
- 空白表型可提供新增列或「開啟新空白頁」。
- 說明必要識別欄、預設值與重複判定。
- 新增成功後，依研究流程決定立即加入名單或下次載入顯示。

### 2.7 刪除

- 刪除與一般儲存分開，不以清空儲存格代替。
- 使用明確刪除按鈕、二次確認並說明刪除範圍。
- 已被後續資料引用時，禁止刪除、改用停用／略過／軟刪除，或交由管理員處理。
- 需要歷史紀錄時使用軟刪除或修改紀錄，不消除稽核軌跡。

### 2.8 完成調查

- 「儲存」與「輸入完成」分開。
- 完成前由後端重新檢查完整性、重複、未處理錯誤及研究條件。
- 完成需二次確認；失敗時保持未完成並列出問題。
- 完成後才可依流程匯入正式表、鎖定批次、開啟比對或建立下一批。
- 若研究不設完成操作（如目前 GEO-TREES），研究文件須說明替代檢查流程。

## 三、頁面共同結構

由上至下依序呈現：

1. 頁面標題。
2. 資料輸入／修改注意事項連結。
3. 操作者與系統日期。
4. 批次建立或開始條件。
5. 工作單位選擇與導覽。
6. 必要的批次／調查資訊。
7. 主輸入或修改卡片。
8. 選用的新增、特殊修改或輔助區塊。
9. 完成調查操作與結果。

標題、注意事項及操作者資訊直接放在內容區上方，不包入陰影卡片。彼此無關的功能分為不同 `text_box`，不可將批次設定、主表、特殊修改與完成操作塞在同一區。

## 四、標題與基本資訊

- 標題使用 `h2`；有年月及期次時優先使用「YYYY 年 M 月＋研究／調查名稱＋資料輸入／資料修改」。
- 下方提供「請先詳閱（資料輸入注意事項）」連結，文字使用研究實際名稱。
- 操作者由登入帳號取得，不可手動修改。
- 輸入日期由系統產生；調查日期另設欄位，不得互相取代。
- 操作者與輸入日期並列，小螢幕可換行。
- 影響資料歸屬的期次、日期與批次狀態，在主表附近再次顯示。

## 五、批次與調查資訊區

- 建立批次使用獨立 `text_box`，標題為 `h6`，下接 `hr`。
- 日期使用原生日期欄位或共用日期元件，格式 `YYYY-MM-DD`。
- 只有研究規則允許才帶預設日期，使用者仍須確認實際日期。
- 最近批次列表只顯示有助判斷的期次、日期、人員及狀態。
- 批次基本資料與逐筆調查資料使用不同儲存操作。
- 建立、修改、略過或刪除均顯示結果，不以重載頁面作為唯一回饋。

## 六、工作單位與分頁導覽

- 使用「選擇要輸入／修改的樣站、樣區、map、Plot」等研究慣用名稱。
- 下拉選單旁提供「上一個／下一個」；兩端保留相同寬度避免跳動。
- 座標式樣方可加快速方格，但仍顯示目前範圍。
- 順序由後端提供，不由前端依顯示文字排序。
- 未儲存時切換工作單位或頁次必須提示。
- 可在選單標示「已完成」，預設不顯示以株數或列數計算的進度 bar。
- 分頁顯示總筆數、目前頁次、上一頁與下一頁。
- 工作單位無資料時顯示「目前沒有資料」，不顯示損壞或只有表頭的表格。

## 七、主輸入／修改卡片

- 使用 `text_box`，不加另一套陰影或卡片系統。
- 標題使用 `h6`，可包含工作單位、期次與模式，下接 `hr`。
- 操作提醒在標題與資料表之間；Handsontable 外層使用 `entrytablediv`。
- 表格上方可放總筆數、頁次與回饋；長表格可上下各放一個相同儲存操作。
- 同頁多種資料各自使用獨立卡片、提醒、回饋與儲存按鈕。

```blade
<section class="text_box">
    <h6>資料類型｜工作單位｜輸入或修改</h6>
    <hr>
    <div class="text_box2 data-entry-note">
        <ul><li>操作提醒</li></ul>
    </div>
    <div class="entrytablediv">
        <div class="app-feedback-note"></div>
        <!-- Handsontable -->
        <p class="data-entry-actions">
            <button class="datasavebutton">儲存</button>
        </p>
    </div>
</section>
```

同頁不可重複 HTML `id`。舊頁常用的 `id="simplenote"` 僅能出現一次；新頁有多個提醒框時改用 class 或唯一 id。

## 八、操作提醒（note）

使用 `text_box2` 視覺：黃色背景、黃色虛線邊框、既有內距與行距，不加陰影。

- 使用 `ul`／`li` 條列，不寫長段落。
- 第一項粗體提醒「輸入或修改後需按儲存，資料才會寫入」。
- 可放無事件的示意 `datasavebutton`，寬度 `auto`。
- 依序說明儲存方式、空白列、特殊值、狀態、欄位關聯、特殊修改與完成操作。
- 頁面只保留當下操作所需摘要，完整研究背景留在注意事項頁。
- 成功、錯誤、載入中與完成訊息使用回饋元件，不放進 note。
- 修改模式說明可修改範圍、唯讀欄位與儲存影響。

## 九、欄位狀態與編輯界線

- 識別、背景及系統計算欄預設唯讀；調查值與備註依研究規則開放。
- 後端必須拒絕唯讀欄位的變更；表格如何設定及顯示唯讀狀態，依 Handsontable 規範。
- 狀態使其他欄不適用時，自動填入研究規定值或停用，後端再次驗證。
- 可正規化大小寫、日期或前導零，但須在研究文件說明；不得猜測有歧義資料。
- 備註可空白時不得阻擋整列；標點與串接規則由研究文件定義。
- 特殊修改、刪除及新增個體不混入一般可編輯欄。

## 十、空白、未輸入與已開始輸入

每個研究必須定義「啟動欄位」或固定名單判斷，後端不可只以任意欄位非空推測。

- 空白表型：例如 Date 為啟動欄；Date 空白代表尚未輸入，儲存時跳過。
- 固定名單型：識別欄本來就有值，須依調查欄判斷完成，不能視為已輸入。
- 已開始輸入的列，所有必要欄位都要驗證。
- 空白列不報錯、不寫入、不計入成功筆數。
- `0000-00-00` 不得為有效日期；舊系統用它表示空白時，新介面送出前正規化為未輸入。
- 缺漏、尚未調查與死亡／消失分開，不由空白自動推論狀態。

## 十一、儲存與驗證

- 重新驗證權限、批次狀態、型別、合法值、欄位關聯、唯一性與資料歸屬。
- 一次可送出整個工作單位，但後端預設以每一筆有效資料作為獨立 transaction：正確資料照常儲存，錯誤資料保留供修正，尚未輸入資料直接跳過。
- 只有資料間具有不可分割的跨列關係時才可整批回滾，且必須在研究文件說明原因、範圍及使用者會看到的結果。
- 不以傳回的唯讀欄值更新資料；使用資料庫識別碼重查。
- 儲存應可安全重試，重送不得不斷新增重複紀錄。
- 回傳新增、更新、跳過筆數及最新版本，由前端同步畫面。
- 前端驗證、錯誤儲存格定位、草稿保留及重複送出防護依 Handsontable 規範；任何前端驗證都不得取代後端驗證。

## 十二、按鈕與操作回饋

- 儲存按鈕在表格下方中央；長表格可在上方再放同一操作。
- 桌面標準寬度 `550px`，小螢幕 `max-width: 100%`。
- 一般儲存用 `datasavebutton`；完成用 `finishbutton`；刪除用危險樣式。
- 訊息使用 `app-feedback-note`，狀態與樣式統一為：`success` 綠色、`partial`／`warning` 橘色、`error` 紅色、`info` 藍色；`noop` 使用一般提示樣式。
- 回饋至少包含結果與筆數；失敗要指引下一步，不只寫「錯誤」。
- 無符合條件資料時提示「沒有可儲存資料」；無變更時提示「沒有需要儲存的修改」。
- 回饋不可只靠顏色，必須有文字。

標準訊息格式：

- 全部成功：`儲存完成：本次新增或更新 N 筆，跳過 M 筆尚未輸入資料。`
- 部分成功：`部分儲存完成：本次新增或更新 N 筆，跳過 M 筆尚未輸入資料，錯誤 E 筆。錯誤資料已保留，請修正後再儲存。`
- 全部失敗：`儲存失敗：錯誤 E 筆。輸入資料已保留，請依錯誤提示修正。`
- 無資料可存：`沒有可儲存資料，跳過 M 筆尚未輸入資料。`

錯誤明細必須指出資料列或穩定識別碼、欄位及原因。畫面先顯示摘要，再定位第一個錯誤；不得只回傳第一個錯誤，也不得因顯示錯誤而清除其他列的輸入值。

## 十三、未儲存變更與離頁保護

- 有未儲存變更時，切換工作單位、頁次、模式、關頁或重載必須提示。
- 開啟特殊修改若會先儲存主表，必須先告知；失敗時停止後續操作。
- Handsontable 的 dirty 偵測、多表狀態、草稿保存及 Livewire 重繪處理依 Handsontable 規範。

## 十四、載入、權限與狀態

- 查詢、切換與儲存顯示共用 loading spinner，不遮住錯誤。
- 無輸入權限時不渲染操作按鈕，後端路由仍驗證權限。
- 完成或鎖定批次預設唯讀；重新開放需權限及操作紀錄。
- 修改、刪除、略過、完成與重新開啟可有不同權限。
- 工作單位完成可用文字標示，預設不用株數進度 bar。

## 十五、修改紀錄與稽核

需要追溯修改的研究至少保存：資料表與紀錄識別碼、修改者、時間、來源、修改欄位、前後值及適用的原因。研究文件應連結人工修正紀錄；短暫的畫面訊息不可取代長期修改紀錄。

## 十六、響應式與可用性

- 主區使用可用內容寬度，不限制窄卡片。
- 基本資訊、導覽與按鈕在小螢幕可換行。
- 不為塞入畫面而縮小到不可辨識；捲動依 Handsontable 規範。
- 按鈕與連結保留 hover、focus、disabled 與鍵盤狀態。
- 錯誤、唯讀、完成、停用不可只靠顏色辨識。

## 十七、既有介面的取用原則

### GEO-TREES

沿用座標導覽、Date 啟動列、逐筆 transaction、錯誤保留、識別欄唯讀、特殊修改與主表分離。雙輸入與研究代碼不是所有介面的必要功能。

### 死亡率調查

沿用 map 導覽、長資料分頁、逐筆成功、錯誤列保留、批次資訊與主表分離、可搜尋選項管理、備註編輯與分頁儲存。團隊管理及死亡率欄位關聯屬研究規則。

### 福山小苗

沿用樣站與上一個／下一個、不同資料分卡片、固定背景資料、錯誤後保留輸入值、特殊修改、新增苗／撿到環獨立流程與最後完整性檢查。舊版回傳欄位由前端相容處理；日後修改 API 時改用標準 `status／message／counts／errors`，既有重複 id、部分行內樣式及舊回饋方式不應複製。

### 種子雨

沿用先建立批次、未完成續傳、最近調查列表、逐筆處理、錯誤後保留輸入值、空白頁新增、已輸入資料檢視、上下儲存及完成後匯入正式表。舊版回傳欄位由前端相容處理；日後修改 API 時改用標準 `status／message／counts／errors`。略過週次與欄位自動補值屬研究規則。

### 小苗實驗

作為新規範優先範例：批次與固定名單、Plot 依序輸入、共用 Handsontable、交易式儲存、離頁保護、完成後建立下一批。D／G 與補資料邏輯見研究文件。

## 十八、實作檢查清單

### 頁面與導覽

- [ ] 標題可辨識研究、期次及輸入／修改模式。
- [ ] 有注意事項、操作者與輸入日期，調查日期另列。
- [ ] 工作單位選擇、順序及上一個／下一個一致。
- [ ] 無資料、載入、完成與鎖定狀態均有明確畫面。

### 卡片與提醒

- [ ] 主區使用 `text_box`、`h6`、`hr`、`entrytablediv`。
- [ ] note 使用 `text_box2`，同頁沒有重複 id。
- [ ] note 說明儲存、空白／啟動列及完成規則。
- [ ] 研究專屬規則放在研究文件，頁面只留必要摘要。
