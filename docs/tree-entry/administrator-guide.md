# 福山每木調查資料輸入與驗證指南

供樣區管理員與資料輸入人員參考｜整理日期：2026-09-10

本指南以本專案的**福山每木調查**為例，將輸入注意事項與驗證規則整理成工作流程，供其他樣區管理員參考。內容以既有第五次調查輸入流程為主，前次比較資料為第四次調查。

文中區分「填寫規範」與「系統檢查」：填寫規範是人員應遵守的要求，系統不一定會完整攔截所有違規內容。通過檢查後仍須核對紙本。

## 1. 先掌握這六件事

1. **依紙本逐筆輸入。** 資料有疑義時查閱原始紀錄，不自行猜測或改成容易通過驗證的數值。
2. **每筆都要填調查日期，並按「儲存」。** 內容留在畫面上，不代表已寫入資料庫。
3. **分清楚 status 與 code。** status 是存在狀態，一格只能填一個；code 是特殊狀態，可依規定組合。
4. **本次改測量點，才使用 C。** 原始 POM 記錯，應走「特殊修改」。
5. **完成輸入後還要檢查。** 福山每木按「輸入完成」；兩次獨立輸入後再做資料比對。
6. **先處理錯誤再離開畫面。** 尤其舊版新增表單，不應假定未儲存內容會一直保留。

## 2. 建議工作流程

| 步驟 | 輸入人員要做的事 | 管理員確認重點 |
| --- | --- | --- |
| 輸入前 | 選對調查次別、第一次／第二次輸入、樣方與小區 | 紙本、名錄與前次資料版本正確 |
| 既有樹 | 逐筆輸入日期、狀態、測量值及註記 | 不在主表直接改位置、牌號或物種 |
| 新增／漏資料 | 先判斷是新發現的枝幹，還是資料庫已有但紙本未列出的枝幹 | 分支須能對應主幹；避免重複新增 |
| 儲存 | 按儲存，逐項修正錯誤，再確認成功 | 未填日期的列可能被跳過，儲存成功不等於全部完成 |
| 完成檢查 | 福山每木每一個 20×20 m 樣方按「輸入完成」 | 漏輸、同株狀態、物種與主分支關係 |
| 二次比對 | 兩人各依紙本獨立輸入，再核對差異 | 回查紙本決定正確值，修正後重新比對 |
| 交付 | 提供完成範圍及尚待查證清單 | 特殊修改與查舊事項有明確處理結果 |

福山每木若在完成後又修改資料，需再次按「輸入完成」。

## 3. 欄位怎麼填

| 欄位 | 意義與填寫方式 | 常見錯誤 |
| --- | --- | --- |
| Date | 每一筆的實際調查日期，使用 `YYYY-MM-DD`，例如 `2026-09-10` | 空白、`0000-00-00`、不存在的日期 |
| 樣方／小區 | 福山以 20×20 m 樣方及 5×5 m 小區定位；新增時小區座標各為 1–4 | 將分支放到不同小區，或選錯樣方 |
| tag | 樹的牌號，保留英文字母及前導零 | 漏零、誤植，造成重號或找不到舊資料 |
| b | 分支號；`0` 為主幹，非 `0` 為分支 | 把分支當成新個體，或缺少主幹 |
| csp | 樹種中文名稱，從該樣區現行名錄選取 | 自行輸入名錄外名稱；新種應由管理員處理 |
| status | 存在狀態，見第 4 節 | 與 code 混用、同格填多個狀態 |
| code | 特殊狀態代碼，見第 5 節 | 用空格或逗號分隔、代碼重複 |
| dbh／h高 | 一般樹木填胸徑；福山樹蕨填 h高。福山填寫規範要求小數點後一位 | 空白與 `0` 混淆、填錯測量項目或單位 |
| POM／h低 | 一般樹木為胸徑測量高度；福山新增樹蕨填 h低。既有樹沿用原 POM；福山新增預設 1.3 | 直接修正原始 POM，卻誤記為本次改測量點 |
| note | 保留仍適用的原註記，再接本次新增說明 | 遺漏 C 的原因、兩次輸入格式不一致 |
| 縮水 | 本次測量值小於前次時勾選；使用 C 時不勾 | 未縮小也勾選，或同時填 C 並勾縮水 |
| 查舊 | 福山用於需調閱舊資料確認的情形 | 只勾選卻未安排後續查核 |
| 特殊修改 | 提出位置、編號、物種、原 POM 等背景資料更正 | 把本次測量資料與背景資料修正混在一起 |

DBH 的門檻以 cm 表示。POM、樹蕨 h高／h低的填寫單位須依該次調查紀錄紙確認，轉用其他樣區時應明列在欄名或操作說明中。

## 4. status：先判斷是整株，還是單一枝幹

以下為福山每木狀態；**`-3` 在一般說明與特殊案例中的用法有差異，應由管理員確認適用情境**。

| status | 意義 | dbh／h高 | code |
| --- | --- | --- | --- |
| 留白 | 枝幹存活，可量測 | 一般樹木 ≥ 1；樹蕨另依高度規則 | 可空白或填合法代碼 |
| `0` | 全株死亡，同株各枝幹應一致 | `0` | 留白 |
| `-1` | 全株失蹤，同株各枝幹應一致 | `0` | 留白 |
| `-2` | 全株枝幹 DBH < 1 cm，但植株仍存活，退出取樣範圍 | `0` | 留白 |
| `-3` | 該枝幹 DBH < 1 cm，但植株仍存活；另有死亡主幹的特殊案例，見下方說明 | `0` | 留白 |

福山舊注意事項的特殊案例，也用 `-3` 表示仍有活分支時的死亡主幹。因此不能只憑代碼數字推定生態意義；跨樣區交換資料時，應附上該次採用的定義。

福山完成檢查會檢查同株狀態：出現全株狀態 `0`、`-1` 或 `-2` 時，不可與其他狀態混用；同株多筆枝幹也不能全部填 `-3`。`-9` 是福山舊系統處理新增資料的內部值，不應當作調查員填寫的狀態代碼。

## 5. code：特殊狀態與組合方式

| 代碼 | 意義 | 填寫要求 |
| --- | --- | --- |
| C | Change，本次更改 POM | POM 必須與前次不同；note 說明原因或位置；不可同時勾縮水；新增樹不可使用 |
| I | Irregular，不正常 POM | 依紙本記錄 |
| P | Prostrate，枝幹倒伏 | 依紙本記錄 |
| R | Ramet，無性拓殖分株 | 只能填於分支，即 b ≠ 0；有多個分支時，在著地的主要分支記 R，note 說明包含哪些分支 |

**組合範例：** `CI`、`IP`、`IPR`。使用大寫、依字母順序、不留空格、不加逗號、不重複；`PI`、`I P`、`I,P`、`II` 都不符合填寫規範。福山既有後端檢查允許的字元，但未完整檢查排序與重複，仍須人工遵守。

## 6. DBH、POM、縮水怎麼一起判斷

以下例子假設為既有普通樹木、status 留白，且日期與其他欄位已正確填寫。

| 前次 → 本次 | POM 情況 | 正確處理 |
| --- | --- | --- |
| DBH 10.0 → 10.4 | 沒變 | 不勾縮水，不因成長填 C |
| DBH 10.0 → 9.8 | 沒變 | 核對紙本後勾縮水 |
| DBH 10.0 → 10.0 | 沒變 | 不勾縮水 |
| DBH 10.0 → 9.8 | 本次確實改了 POM | code 填 C，輸入新 POM，note 說明，不勾縮水 |
| 任意 DBH | 填 C，但 POM 與前次相同 | 不通過；核對是否填錯 C 或 POM |
| 任意 DBH | 原始 POM 記錯，本次未改測量點 | 用「特殊修改」提出原 POM 更正 |

填 C 是紀錄實際改變 POM，不能只為了讓縮小的 DBH 通過檢查。異常縮小或增長過多時，應查前次紙本；通過數值驗證並不代表測量正確。

### 福山特殊情形

- **樹蕨：** G 開頭牌號的 dbh／h高欄填高度，以前次 h高比較是否縮小，不套用普通樹木 DBH ≥ 1 的門檻。
- **DBH < 1 cm 的實測補記：** 福山舊說明另提供「主表填 1，再於特殊修改的 dbh(<1) 填實測值」流程。這與 `-2`／`-3` 狀態記錄須先依調查目的區分，由管理員確認適用情況；不可直接當成其他樣區的通則。
- **無法測量：** 福山舊說明使用 `999`。這是特殊值，不是實測胸徑；其他調查採用前應確認是否允許，以及後續分析如何排除。
- **前次 POM 錯誤，且本次又更改 POM：** 例如系統原值為 1.3，現場前次其實不是 1.3，本次才改成 1.3，應由管理員先修正原始資料，再輸入本次結果。

## 7. 新增樹與「漏資料」要分開處理

| 情況 | 處理方式 |
| --- | --- |
| 本次新發現、資料庫沒有的枝幹 | 新增資料，不勾「漏資料」 |
| 資料庫已有，但本次紙本／工作表未列出 | 核對既有紀錄後勾「漏資料」 |
| 系統顯示重號，且已是本次應調查資料 | 回查原列與牌號，避免重複新增 |
| 勾漏資料但查無此樹 | 查核編號及資料來源，由管理員判斷 |

福山新增時，日期、樣區位置、tag、b、csp、dbh／h高必須完整，POM／h低也要確認。普通樹木 DBH ≥ 1，code 只使用 I、P、R，不可填 C。

新增分支前，先確認主幹已存在；建議先存主幹，再存分支。福山新增分支需放在主幹所在小區；R 分株若實際跨小區，仍新增於主幹小區，將實際位置寫入 note 並標在地圖上。

福山舊程式也檢查牌號格式：普通樹木為 6 碼，並檢查與樣方 x 編號的關係；樹蕨為 G 加 6 碼，G 後前四碼對應補成兩位數的樣方 x、y。跨樣區採用前須另訂牌號規則，R 相關例外應由管理員核對。

漏資料的基本位置與物種等資料應與既有紀錄相符。福山舊介面新增樹可修改、刪除；牌號輸錯需刪除重輸。漏資料儲存後視為舊樹，需要刪除或變更基本資料時由管理員處理。

**舊版表單注意：** 福山原注意事項記載，新增表單未通過檢查的資料雖留在畫面，按「輸入完成」可能清除。請先完成儲存及錯誤修正，再做完成檢查。

## 8. note 與特殊修改

### note 的統一寫法（填寫規範）

- 保留仍有效的原 note，本次新增內容接在後面，以中文句號「。」分隔。
- 中文用中文標點，英文符號與阿拉伯數字用半形。
- 多個分支以「、」分隔，例如 `包含分枝1、2、3`。
- 數字與單位間留一個空格，例如 `1 cm`；數字與 `<`、`=`、`>` 之間不留空格。
- 座標用半形括號，例如 `(1, 1)`。
- 主幹牌移到分支 2，統一寫 `TAB=2`。
- 「縮水」「查舊」「漏資料」使用對應勾選欄位，不以 note 文字代替。
- POM 數值填在 POM 欄；C 的原因仍須寫在 note。移除舊 POM 備註前，先確認必要資訊已記錄於正確欄位。

福山常用縮寫：I＝凹凸不平、I+＝凸、I-＝凹、AR＝長不定根、GR＝頭尾接地生根、GR+＝全株接地生根、U＝根拔。舊 note 的 S 表示縮水，新輸入以縮水勾選欄為準。note 的 I 與 code 的 I 分屬不同欄位，應依紙本內容判讀。

### 特殊修改的原則

只填需要更正的欄位，保留原始紀錄供追查。主表記錄本次調查，特殊修改提出背景資料更正，仍需管理員檢視後續處理結果。

福山若將分支改為獨立個體，除新牌號外，分支號 b 也需改為 `0`。送出後應再次確認特殊修改內容確實保留了分支號 `0`。

## 9. 系統檢查分成三個階段

| 階段 | 檢查內容 | 仍須人工確認 |
| --- | --- | --- |
| 單筆／儲存 | 必填欄位、數值、status 與 DBH／code、R 與分支、C 與 POM／note、縮水與前次值、新增重號及主幹 | 實測值是否抄對、note 是否真正解釋原因、異常成長是否合理 |
| 福山「輸入完成」 | 是否漏日期；同株多筆枝幹的主幹、位置、status 與物種一致性 | 舊程式檢查有適用條件，仍應人工確認孤立分支及 R 的位置 |
| 第一次／第二次比對 | 同一枝幹的兩次輸入是否相符 | 差異應回查紙本；兩次一致仍可能同時抄錯 |

### 常見訊息與處理

| 訊息／情況 | 處理方式 |
| --- | --- |
| 需有日期／DBH | 補齊該筆資料，不用 `0` 代替未知測量值 |
| status 有值，DBH 需為 0／code 不得有值 | 回查整株或枝幹狀態，讓三欄一致 |
| DBH 小於前次 | 查紙本；確有縮水則勾選，確有改 POM 才填 C |
| POM 與前次不同，需有 C | 判斷是本次改測量點，還是原始 POM 記錯 |
| C 需 note／POM 應不同 | 補真實原因與新測量高度，或更正誤填的 C |
| R 只能記錄在分支 | 檢查 b 及主分支身分 |
| 重號／缺少主幹 | 查既有資料、漏資料狀態與主幹是否已儲存 |
| 同株 status 不一致／不能全為 -3 | 回查是否為全株狀態，並核對該次 -3 定義 |

## 10. 管理員交付與採用檢查清單

福山既有系統的檢查不能完全取代人工複核。例如 code 的排序與重複仍須人工確認；完成檢查的同株關係檢查主要針對同株多筆資料，不宜據此認定所有孤立分支都已被找出。日期應主動使用真實的 `YYYY-MM-DD` 日期，小數位與 note 格式也應統一。

### 完成一批資料後

- [ ] 每個應調查枝幹都有日期與測量／狀態資料，且已確認儲存成功。
- [ ] 每個 20×20 m 樣方已通過「輸入完成」，修改後也已重新檢查。
- [ ] 第一次與第二次輸入已比對，差異已回查紙本並修正。
- [ ] 查舊、特殊修改、異常測量值及未確認樹種都有處理結果或待辦紀錄。
- [ ] 已記錄完成範圍、處理人員與尚待管理員確認的事項。

### 提供另一樣區採用時，先填好這份清單

- [ ] 調查名稱、次別、適用日期及管理員窗口。
- [ ] 樣方／小區尺寸、位置欄位、牌號與分支編碼方式。
- [ ] 現行物種名錄及新增物種的處理流程。
- [ ] 每個 status 的完整定義，尤其 -3 的適用情境。
- [ ] DBH、POM、樹蕨高度的單位、小數位與取樣門檻。
- [ ] DBH < 1、無法測量及 999 等特殊值的處理方式。
- [ ] 前次比較資料版本，以及 R 分株跨小區等例外。
- [ ] 儲存失敗是否部分寫入、未儲存列是否保留，以及完成檢查的方式。
- [ ] 兩次獨立輸入、差異修正、查舊與特殊修改的負責人。
